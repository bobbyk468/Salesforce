## What We’re Asking You To Do

1. **Architecture** — Is the split between registry data (`CertSpikeBodyData`), `CertificationBodyTemplate`, and bespoke bodies (`AdministratorCertBody`, `Developer1CertBody`) reasonable? Any coupling or duplication concerns?
2. **Type safety** — Does the discriminated union on `body.template` cover all cases? Are there paths where `AssociateTemplate` receives a non-associate body?
3. **Routing & static generation** — `generateStaticParams` derives from `SPIKED_CERT_SLUGS`. Could slugs drift out of sync with `certifications-data` or sitemap?
4. **Legacy escape hatch** — Empty `LEGACY_CERT_SLUGS` + `loadLegacyCertBody` returning `null`: is the remaining `[slug]/page.tsx` legacy branch dead code worth removing or worth keeping?
5. **Content model** — `RichSectionBlock` with optional `bodySegments` vs plain `body`: XSS surface (we only render structured segments, not arbitrary HTML). Is the pattern sound for gradual rich text restoration?
6. **Practice-test pages** — JSON-driven `scenarioTips` for `administrator-practice-test` and `email-specialist-practice-test`: any obvious content or TOC/`id` consistency issues from a product/SEO lens?
7. **Top 3–5 actionable recommendations** — Prioritized for a small team.

Assume the repo is the source of truth; the live site may lag deploys.

## Summary of Changes (For Reviewers)

### Dynamic certification route

- **Single route:** `src/app/certifications/[slug]/page.tsx` serves all catalog certification URLs under `/certifications/[slug]`.
- **Static params:** `generateStaticParams()` uses `SPIKED_CERT_SLUGS` from `src/lib/cert-page-spike/registry.ts`.
- **Body resolution:** `certSpikeBodyBySlug[slug]` picks JSON/hand-authored markers; `notFound()` if slug not spiked.

### Registry merge order

`certSpikeBodyBySlug` is built from:

1. Spread **`promotedAssociateCertBodies`** (84 JSON files under `promoted-associate/`).
2. Spread **`legacyCertSpikeBodies`** (currently **empty** — `LEGACY_CERT_SLUGS = []`).
3. Explicit overrides: `ai-associate`, `app-builder`, `administrator`, `advanced-administrator`, **`developer-1`** (PD1).

Hand entries **override** promoted entries if a slug ever collided (intentional).

### Template types (`src/lib/cert-page-spike/types.ts`)

| `template`   | Render path |
|-------------|-------------|
| `associate` | `CertificationBodyTemplate` → `AssociateTemplate` (card, exam prep, key concepts, scenario tips, heatmap, practice questions, etc.) |
| `app-builder` | Same component → `AppBuilderTemplate` (reordered sections, extra blocks) |
| `admin`     | `AdministratorCertBody` only (marker body `{ template: 'admin' }`) |
| **`pd1`**   | **`Developer1CertBody` only** (marker `{ template: 'pd1' }`) — **new** |
| `legacy`    | Dynamic import via `loadLegacyCertBody` (currently always `null`) |

### PD1 migration (developer-1)

- **Before:** Only remaining “legacy” TSX in `src/components/certifications/cert-bodies/developer-1.tsx`, loaded by `loadLegacyCertBody`.
- **After:** `src/components/certifications/Developer1CertBody.tsx` (default export), same UX/content intent as the old file; **`src/lib/cert-page-spike/developer-1-data.ts`** exports `developer1CertPageBody` and `DEVELOPER_1_SLUG`.
- **`SPIKED_CERT_SLUGS`** explicitly includes `DEVELOPER_1_SLUG` so PD1 is not dropped when legacy list is empty.

### Promoted associate JSON (84 certs)

- Bodies live in `src/lib/cert-page-spike/promoted-associate/*.json`.
- Index: `promoted-index.ts` (auto-generated by `npm run cert:promote-associate`).
- Promotion script: `scripts/promote-all-certs-to-associate.mjs` (also regenerates legacy loader files when run).

### Rich blocks (optional)

- **`RichSectionBlock`:** `heading`, `body` (string), optional **`bodySegments`** (`IntroSegment[]` — text, link, strong).
- **`CertificationBodyTemplate`:** `KeyConceptsSection` and `ScenarioTipsSection` render `bodySegments` when the array is non-empty, else `body`.
- **Intent:** Restore bold/links in promoted content **without** `dangerouslySetInnerHTML`. Most JSON still uses plain `body` only.

### Practice test copy

- **`administrator-practice-test.json`** and **`email-specialist-practice-test.json`:** `scenarioTips` expanded (specific headings, intro tied to heatmap + main cert page, five blocks each) replacing thinner generic placeholder copy.

### Tooling

- **`scripts/cert-migration-status.mjs`** — counts catalog vs registry; **`DATA_TEMPLATE_SLUGS`** includes `developer-1` with the other hand-maintained slugs.
- **`npm run build`** — should pass with zero TypeScript errors after these changes.

## Known Limitations (Honest Context for Review)

1. **84 promoted certs** were extracted from legacy TSX with **HTML stripped to plain text**; restoring emphasis at scale needs either **`bodySegments` in JSON**, a promoter script change, or recovered sources (not all history may exist in git).
2. **`cert:migration` script** does not parse `registry.ts`; it uses **`DATA_TEMPLATE_SLUGS` + JSON dir + generated legacy file** — must stay aligned manually when adding new hand slugs.
3. **Re-running `cert:promote-associate`** with new files in `cert-bodies/` will regenerate legacy loader files; with an empty `cert-bodies/` folder, legacy stays empty (expected).
